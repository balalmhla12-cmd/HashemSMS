# HashemSMS — جرد الفجوات وخطة الاستكمال

تاريخ الإعداد: 2026-10-21
الفرع المستهدف: `phase1-ui`
الحزمة المحمية: `com.hashem.sms`

## قواعد غير قابلة للتفاوض

1. هذا المستند جرد وخطة فقط؛ لا يحذف أو يعطّل أي ميزة قائمة.
2. لا تغيّر منطق الرسائل أو مخطط قاعدة البيانات أو الأذونات أو معرّف الحزمة دون مراجعة مستقلة وموافقة صريحة.
3. كل مرحلة تغييرات إضافية صغيرة في commit مستقل؛ لا تنتقل المرحلة التالية إلا بعد نجاح أحدث GitHub Actions.
4. لا تغيّر حدود Lint أو baseline ولا تستخدم suppress/ignore لإخفاء مشكلات.
5. افصل «موجود في الكود» عن «اختُبر على هاتف حقيقي». بناء APK وحده ليس إثباتًا للتشغيل.
6. لا تدمج PR إلى main دون موافقة المستخدم الصريحة.
7. أي إضافة جديدة يجب أن تكون قابلة للتعطيل/الاختبار ولا تكسر الأرشيف والحظر والمهملات والرسائل المجدولة والجماعية والمجموعات والنجمة والبحث وقواعد التوجيه والرسائل الفاشلة والشريحتين والإشعارات.

## ما هو موجود بالفعل بحسب المستودع

المشروع تطبيق Android أصلي بلغة Java، وواجهته عربية، وحزمته `com.hashem.sms`. يضم حاليًا شاشة المحادثات، شاشة المحادثة، بحثًا، تبويب جهات اتصال، وقسم «المزيد»/شاشات إدارة. هذه خلاصة قراءة README وPROJECT_STATE وPROGRESS وملفات التطبيق الأساسية، وليست شهادة اختبار يدوي شامل.

### ميزات موجودة أو ممثلة في الكود

- محادثات ورسائل SMS، ومزامنة مع مخزن رسائل Android وفق صلاحيات التطبيق الافتراضي.
- بحث في المحادثات؛ بحث/عرض جهات الاتصال مع صورها ومراقبة تغييرات جهات الاتصال.
- أرشفة المحادثات، حظر الأرقام، المهملات والاستعادة/الحذف النهائي، والرسائل المميزة بنجمة.
- تحديد متعدد وإجراءات جماعية على المحادثات/الرسائل بحسب الشاشة.
- إرسال جماعي، استيراد مستلمين من نص/CSV، تخصيص الرسالة بالمتغير `{name}`، ومجموعات مستلمين قابلة لإعادة الاستخدام.
- جدولة الرسائل، إلغاء الموعد، ومحاولة استعادة المواعيد بعد إعادة تشغيل الجهاز أو تغيير الوقت/المنطقة الزمنية.
- عرض الرسائل التي تعذر إرسالها ومحاولة إعادة إرسالها أو استخدام قاعدة توجيه بديلة بعد تأكيد المستخدم.
- قواعد توجيه مسماة، اختيار شريحة/اشتراك الإرسال في مسارات الإرسال المتاحة.
- إشعارات محادثات مع رد مباشر وتعليم كمقروء.
- إرسال واستقبال SMS عبر خدمات Android ومكونات استقبال/إرسال وتقارير التسليم.
- دعم الوضعين الفاتح والداكن، RTL، موارد ألوان وتباين مفحوصة، وأيقونات مخصصة.
- توجد مكونات/تصريحات استقبال MMS في المشروع، لكن README يصرح بأن دعم MMS غير مكتمل؛ لا تُعامل على أنها ميزة مكتملة.
- يوجد APK تجريبي ونجحت خطوات البناء والاختبارات وLint في مهمة البناء المسجلة؛ لم يُثبت بعد اختبار كامل على جهاز فعلي.

### واجهات ينبغي جردها/استكمالها قبل وصفها بأنها مكتملة

- شاشة إعدادات واضحة ومتكاملة لكل خيارات التطبيق وإشعاراته.
- شاشة إنشاء/تعديل المسودة واستعادتها عند الخروج أو إعادة تشغيل التطبيق؛ المسودات مدرجة في خارطة المشروع كميزة لم تنفذ بعد.
- تجربة تبويب جهات الاتصال من البداية للنهاية، بما في ذلك الصلاحيات والبحث والبدء بمحادثة.
- تفاصيل شاشة «المزيد» وترتيب كل أدوات الإدارة، مع التحقق من أن كل عنصر يصل إلى شاشة عاملة.
- واجهات إعدادات الجدولة، اختيار الشريحة، قواعد التوجيه، الرسائل الجماعية والمجموعات، الفاشلة، المحظورة، المؤرشفة، المميزة والمهملات.
- حالات فارغة، تحميل، خطأ، رفض صلاحية، عدم وجود شريحة، فشل الإرسال، وفشل استعادة الموعد.
- شاشة تأكيد تعيين التطبيق كتطبيق SMS الافتراضي، وحالات رفض الدور أو سحبه لاحقًا.
- واجهة مرفقات متكاملة لـ MMS (صور/فيديو/صوت/ملفات ومعاينة وحدود الحجم) غير مكتملة.
- إعدادات النسخ الاحتياطي والاستعادة والتصدير/الاستيراد؛ موضوعة ضمن المؤجل حاليًا.
- قفل التطبيق والخصوصية؛ مدرجان ضمن خارطة المشروع السابقة، لكنهما غير معتمدين حتى مراجعة الكود واختبارهما.
- تحسينات إدارة المحادثات مثل تثبيت المحادثة، كتمها، تخصيصها، تذكيرات الرسائل، وقوالب الرد؛ مقترحات جديدة وليست ادعاءً بأنها مفقودة بعد فحص كل سطر.

## المقارنة مع Google Messages

تتضمن تجربة Google Messages، بحسب صفحات Google الرسمية، إلى جانب SMS/MMS: RCS حيث يتوفر، مشاركة وسائط عالية الجودة، مؤشرات الكتابة وإيصالات القراءة، مجموعات RCS متقدمة، ربط الويب/الأجهزة، حماية الرسائل المزعجة والتصيد، الردود والاقتراحات الذكية، رسائل صوتية وموقعًا، وتخصيص المحادثات وردودًا تفاعلية/Photomoji وبعض ميزات الذكاء الاصطناعي. تختلف الإتاحة حسب البلد والجهاز والناقل والحساب.

لا يمكن افتراض أن تطبيق طرف ثالث يستطيع تنفيذ RCS الخاص بمنظومة Google بمجرد بناء واجهة له؛ يلزم مزود/اعتماد وبروتوكول متاح. لذلك تُعامل RCS والتشفير الطرفي الخاص به كمسار بحث مستقل، ولا يُعرضان للمستخدم كأنهما موجودان أو آمنان دون بنية موثقة واختبارات مستقلة. كما أن SMS/MMS التقليديين لا يوفران ميزات RCS مثل مؤشرات الكتابة وتشفير الطرف إلى الطرف.

## خارطة مراحل مقترحة

### المرحلة 0 — تثبيت خط الأساس والجرد (إضافية فقط)
- توثيق الميزات والواجهات والاختبارات والقيود كما هي.
- إنشاء مصفوفة لكل ميزة: كود موجود؟ واجهة موجودة؟ اختبار آلي؟ اختبار جهاز؟.
- مراجعة أحدث Actions والفرع قبل أي تعديل.
- المخرج: هذا الملف، ثم جرد تفصيلي قابل للتحديث دون تغيير سلوك التطبيق.

### المرحلة 1 — إكمال واجهات الأساس الناقصة
- الإعدادات والإشعارات، المسودات، وتدفق جهات الاتصال/محادثة جديدة.
- تحسين الحالات الفارغة والأخطاء والصلاحيات وإمكانية الوصول.
- الحفاظ على تصميم HashemSMS الحالي والألوان والهوية وRTL.
- اختبارات حفظ المسودات واستعادتها، انتقال الشاشات، وعدم فقدان حالة البحث/التحديد.

### المرحلة 2 — موثوقية الرسائل والاختبار على الجهاز
- اختبار إرسال/استقبال SMS، تسليم الرسائل، الرد من الإشعار وتعليم كمقروء، الشريحتين، إعادة التشغيل والجدولة، الحظر والأرشفة والمهملات والفاشلة.
- إصلاح العيوب المثبتة فقط، مع اختبار انحدار للميزات المحمية.
- التحقق من تعيين التطبيق الافتراضي والتعامل مع سحب الصلاحيات.

### المرحلة 3 — MMS والمرفقات
- تحديد نطاق دعم MMS أولًا، ثم تنفيذ استقبال/إرسال الصور والصوت والفيديو والملفات والمعاينة ومعالجة الفشل.
- اختبارات حدود الحجم والاتصال والشرائح والرسائل متعددة الأجزاء.
- لا تبدأ قبل تدقيق التنفيذ الحالي لأن وجود MmsReceiver لا يعني اكتمال الميزة.

### المرحلة 4 — النسخ الاحتياطي والتصدير والاستعادة
- تصدير/استيراد قابل للتحقق، نسخ احتياطي مشفر اختياريًا، معاينة ما سيُستعاد، معالجة التعارضات وعدم التكرار.
- لا ترفع الرسائل أو جهات الاتصال إلى أي خدمة خارجية افتراضيًا.

### المرحلة 5 — الخصوصية والأمان
- قفل اختياري للتطبيق مع قفل تلقائي وبصمة/قفل الجهاز حيث يدعم النظام، مع استثناءات واضحة للإشعارات.
- أدوات محلية لمراجعة المرسلين المزعجين/المحظورين؛ تجنب تصنيفًا آليًا مضللًا أو إرسال بيانات الرسائل للخارج.
- توثيق التخزين والصلاحيات والنسخ الاحتياطي.

### المرحلة 6 — ميزات إنتاجية وتميّز
- تثبيت المحادثات، كتم/تذكير، قوالب رد قابلة للتخصيص، رسائل متابعة/تذكير، أدوات تنظيم اختياري.
- تحسينات وصول: حجم خط، دعم قارئ الشاشة، تباين، وتقليل الحركة.
- بحث متقدم في محتوى الرسائل مع فلاتر حسب التاريخ/المرسل/النوع، بعد قياس الأداء والخصوصية.

### المرحلة 7 — دراسة الميزات المتقدمة والتوزيع
- تقييم واقعي لتكامل RCS؛ لا ادعاء بالتوافق قبل إثباته تقنيًا.
- تقييم الربط مع الحاسوب/الأجهزة دون تسريب محتوى الرسائل.
- إعداد توقيع إصدار إنتاجي، حماية مفاتيح التوقيع، مراجعة الخصوصية، واختبار على أجهزة وإصدارات Android متعددة.

## بوابة قبول كل مرحلة

- لا فقدان لميزات سابقة ولا تغييرات غير معلنة.
- أحدث GitHub Actions على commit المرحلة ينجح؛ Lint لا يتجاوز baseline (15 تحذيرًا حاليًا حسب آخر سجل).
- اختبارات وحدات وانحدار مناسبة للميزة.
- فحص يدوي على جهاز حقيقي قبل اعتبار الوظائف التي تعتمد على الهاتف مكتملة.
- توثيق ما اختُبر وما لم يُختبر، مع SHA والرابط إلى Actions.
- لا دمج إلى main دون موافقة المستخدم.
